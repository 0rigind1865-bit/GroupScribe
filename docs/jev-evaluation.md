# Jev 判斷模型要不要導入——評估報告（2026-10-10）

## 一句話結論

**不導入（no）。** 三位評審一致說「現在不要」（信心 0.85、0.72、0.72），最終裁決同樣是 no：以現在的規模，換 Jev 省不到錢、也沒證據會更準，卻要先改三份條款、多一家美國處理者、花 4～8 週工時。先做一件零風險的小事（0.25 人日加「用途標籤」），等條款、中文實測、規模三個門檻成立再回頭看。

## 先講白話

1. Jev 是一種只會「選答案、給機率」、不會寫字的 AI，很便宜、很快。
2. 它能幫群記做是非題，例如「這句是不是在記帳」「這兩件事是不是同一件」。
3. 但它中文沒英文好、資料要送到美國一家上市不到一個月的新公司，而群記現在用免費規則就做得到，全月 AI 費不到一美元。
4. 要接進來得先改隱私頁和合約、寫 4～8 週的程式，換到的是每月省不到台幣 5 元。
5. 現在不做；先在程式裡加一個「用途標籤」把各種 AI 費用量準，等條款、中文實測、規模三件事成立再回頭看。

## Jev 是什麼（只寫查證過的）

- **公司**：TypeSafe AI, Inc.，總部舊金山（服務條款 13(e) 條、隱私政策）。三位共同創辦人：Diogo Almeida（執行長，前 OpenAI 研究員、InstructGPT 論文第 4 作者）、Erik Gafni、Sasha Sheng（TechCrunch、Fortune、SiliconANGLE）。「2024 年創立」只有新聞稿與媒體間接佐證，官網沒寫。
- **時間與錢**：2026-09-15 上市（Business Wire 新聞稿、The Register、npm 套件發布時間一致）。10/9 官方部落格宣布 Series A（第二輪募資）8.7 億美元、估值 75 億美元，a16z 領投；主流媒體尚未獨立報導，只能算官方說法。
- **它做什麼**：不生成文字、程式碼或對話。輸入是「一段狀態文字＋一題或多題」，回答只有三種題型：Choice（選擇題）、Score（評分）、Noul（是非題）。可一次問多題。每次請求上限 64k token（token＝AI 算字數的單位，中文一個字約 1～2 個），狀態加最長一題 32k。**只收文字**，不收圖片、聲音（docs.typesafe.ai/models）。
- **回傳什麼**：選擇題與評分題回各選項機率＋信心分數（0～1）；**是非題只回一個 0～1 的機率，沒有信心分數**，要自己算。信心分數不是模型另外的訊號，是從機率換算出來的統計量；獨立評測（Vals AI 10/6）說它「幾乎不提供機率以外的額外訊號」（docs.typesafe.ai/confidence）。
- **價錢**：輸入每百萬 token 0.042 美元，**輸出免費**（docs.typesafe.ai/models；Vercel、Cloudflare 轉售同價）。官方自承「無法證明定價未被補貼」。速率限制「可不經通知變更」，三週內第三方記錄過三種不同數字。
- **速度（獨立量測，廠商數字不採用）**：美國直連約 0.10～0.25 秒（Vals AI、LiteLLM）；台灣經 OpenRouter 0.37～0.4 秒（vocus）；Cloudflare 量到中位 0.524 秒、p95（100 次中最慢的第 5 次）0.536 秒；AI/ML API 0.84 秒。**沒有人從台灣直連 api.typesafe.ai 量過。**
- **中文**：官方明寫「英文是主要訓練語言，含中日韓在內的其他語言有支援但不等效，請用自己的內容測」；沒有任何官方多語言評測。社群自測：台灣作者 41 則新聞，分類一致率繁中 72%、英文 91%；信心 ≥0.95 時一致 94%，0.5～0.95 區間約五成（vocus，小樣本、比對對象是另一個 AI 不是人工標註）。簡中 130 則人工標註 97.7%（judgekit，作者自建小集）。
- **官方自列弱點**（docs.typesafe.ai/model-jaggedness，2026-10-02 審閱）：字面理解、不會算數、日期當文字讀、雙重否定、無關內容多就掉準確度、不把輸入當敵意內容（提示注入）、指令矛盾、選擇題偏向第一個選項、不會生成文字。獨立研究證實注入有效（Check Point 27 回合 25 次成功；arXiv 2609.28613 注入會移動機率）。
- **資料去哪**：服務託管美國；13 家子處理器全在美國，無歐盟區域（trust.typesafe.ai）。**不拿客戶資料訓練**的承諾成立（隱私政策＋企業頁）。**保留期無固定天數**；零資料保留只給企業客戶（有爭議，見查核表）。
- **怎麼用**：有公開 API 文件、npm 與 PyPI 套件（Python 套件三週內兩次破壞性變更）；REST 端點（直接用網址呼叫、不必裝套件）實測存在。9/20 起不用排隊，9/22 曾因需求暫停註冊，9/27 恢復但新帳號不再送免費額度。「early access」現在只剩首頁的標籤。
- **67.8% 準確率**：是 TypeSafe 自家 evals.typesafe.ai 四個自建工作流的平均，「對」的標準是另外兩個 AI 回答的平均，不是人工標註、不是第三方、不是真實資料。獨立評測（arXiv 2609.24574，7,977 筆人工標註）15 題有 14 題落後最佳 LLM。
- **競品**：OpenAI 10/6 推出同類 Decisions API（輸入 0.10 美元／百萬、可收圖片）；Cloudflare 10/1 推出 Clef（格式相容）。

## 風險

**條款與隱私（上線前就卡住）**
- 隱私頁處理者清單是封閉的：src/app/privacy/page.tsx:62 只列 Supabase、Google Gemini、LINE，:64「不會提供給上述以外的第三方」；:104–105 跨境只點名兩家。再加一家＝先改頁面並依 :114 通知組織管理員。
- :31 明文「貼圖、『好』『收到』等短訊息不做 AI 分析」。用模型判斷低資訊或確認語，等於每則短訊息都先送 AI——直接違約。
- 設計夥伴合約 docs/legal/design-partner-agreement.md:26（付費層不訓練）、:33（終止後 30 日刪除含備份）、:37（72 小時通報）。Jev「不訓練」成立；「30 日刪除」對 Jev 無固定保留期、零保留只給企業客戶——**有爭議**，兜不住。
- LINE 官方帳號條款 5.5(6) 的書面詢問尚未答覆（docs/business-plan.md:170）；再加一家美國處理者是擴大同一條曝險。
- 離線評測用真實訊息也是外送。條款更新前只能用 tests/fixtures/golden 的虛構對話（沒有私訊與問句樣本）或自己公司的訊息（違反產業無關原則、數字不能當通用結論）。

**準確度**
- 繁中證據近乎零：唯一自測 41 則、比對對象是另一個 AI；中間信心帶形同擲硬幣；中文信心常飽和到 1.00（awesome-jev-zh 15 則有 12 則）。
- 官方弱點正好打中最想替換的判斷：不會算數（單價總價）、日期當文字（LATEST_RE）、無關內容多（回答把關）、偏向第一個選項（報帳分類）、字面理解（確認語）、不防注入（所有群訊息都是使用者可控內容）。
- 在「假陽性比假陰性貴」原則（docs/principles.md:19–26）下，Jev 要有價值就得提高召回，等於把「漏」換成「錯」；沒有繁中校準前是逆著原則走。

**供應商**
- 上市 25 天；註冊暫停過；速率限制三週內改過三次；定價可能補貼；可用率 99.837%、有 2～18 分鐘中斷紀錄；Python 套件兩次破壞性變更；同月競品進場、類別格式還在變。

**工程與維運**
- 判斷在 webhook（LINE 推訊息給我們的通道）回覆路徑上、在訊息落地之前；遠端逾時會吃掉約一分鐘的 replyToken（LINE 回覆憑證）。src/providers/gemini.ts 現在連逾時都沒有。
- 必須做硬逾時 ≤3 秒＋斷路器＋退規則＋設定頁計數卡＝永久維護兩套判斷。單一容器下斷路器只能放記憶體，重啟歸零。
- 新環境變數 JEV_API_KEY → NAS 要 docker rm -f 重建容器（architecture.md §10.3）。
- 不新增 npm 依賴鐵則：必須走純 REST，不裝 SDK。

**對產品定位是扣分**
- Jev 不產生任何文字，判斷無法向把關者解釋。「什麼時候會回」變不可預期，牴觸「別讓我想」與 PERSONAL_NOTICE 的使用者承諾。

## 替代方案（不用 Jev 也能做到的）

1. **維持規則，照實際數據調**（0 元、0 毫秒、0 新廠商；這是 ingest.ts:114 註解自己寫的升級路徑）：CONFIRM_RE 補「好啊／可以啊／行／嗯好／OK的」；dropDupes 的 key 改模糊比對（去標點、子字串、同日容差）；抽取合批調 quietMs／MAX_EXISTING 縮固定開銷。
2. **先量再說**（0.25 人日）：在 src/providers/gemini.ts 的 post()／bump() 加 purpose 標籤寫進 api_usage。本報告所有「判斷型佔 0.2%」「抽取空轉 36%」都是 ±20% 的推估。
